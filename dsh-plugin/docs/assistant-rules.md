# 侧边对话（医师角色）规则说明

版本：`physician-side-chat-v2`（2026-11-23，新增草稿补充模式）  
实现位置：`client.js`（右侧对话面板）＋ `index.js`（HTTP 路由与模型调用）＋ `runtime/assistant.js`（提示词、脱敏、校验、兜底）＋ `runtime/physician_rules.json`（规则单一来源）

## 1. 它是什么

工作站内的“循证对话”是一个**只解释、不下判断**的侧边窗口：

- 回答“这个 ΔT 意味着什么、要不要复测、有什么证据和局限、哪些情况要就医”这类问题。
- 风险等级、ΔT、质量门禁结论来自本地 Python 规则引擎（`runtime/plugin_service.py` 的 `thermal.analyze`），模型只负责组织语言。
- 不确诊、不排除感染、不判断病原体、不推荐抗生素，不写入档案或正式报告。

它与主对话的分工：主对话负责调用工具、写档案、生成报告草稿并留下审计；侧边窗口负责解释和追问，回答不进入会话日志，也不直接进入患者档案（草稿模式下的对话记录只保存在草稿里，归档后随草稿只读）。

## 2. 三层执行

| 层 | 位置 | 作用 |
|---|---|---|
| 提示词 | `buildSystemPrompt()` | 规则全文、本地规则结果、证据摘录、只读历史进入系统提示；用户问题单独作为一条 user 消息。 |
| 服务端校验 | `validateAnswer()` | 回答展示前检查确诊/排除/用药/病原体/绝对化措辞、等级一致性、证据编号缺失、报告越界；不通过则**丢弃模型文本**并改用规则模板；界面已固定显示免责声明，正文不再逐条追加。 |
| 界面 | `AssistantPanel` | 每次回答附带本地等级徽标（模型无权修改）、模型/规则模板来源、拦截原因；输入区常驻免责声明与“仅发送去标识化指标”说明。 |

等级与 ΔT 在界面上由独立徽标渲染：没有规则结果时显示“待本地规则校验”，拿到规则结果后才显示等级，避免客户端预览与引擎结论冲突。回答元数据带 `measurementId`，只有与当前测量一致时界面才展示该等级；导入新测量会清空对话。即使模型措辞出错，读者看到的等级仍来自规则引擎。

## 3. 规则要点（JSON 分为 8 组 + `draft` 章节，覆盖以下 10 项 + 草稿模式）

1. **判断归属**：ΔT、阈值、等级、门禁只能逐字引用本地结果；不得把其他等级当作本次结论。
2. **禁止确诊与排除**：不写确诊、排除、已控制、无需处理、无需就医；不判断病原体、耐药性，不推荐药物与剂量。
3. **证据与引用**：涉及研究阈值、敏感度/特异度、疗效时对应 `E001–E004`；不得编造文献、指南、DOI、阈值；证据未覆盖时写明不能外推。
4. **低温与不一致**：ΔT 为负按灌注不足/缺血提示；绝对温度与 ΔT 不一致时并列说明。
5. **数据与隐私**：只使用去标识化数值；不索取姓名、证件号、住院号、联系方式、住址；不输出路径、密钥或影像。
6. **不确定性与复测**：说明单次测量假阳性、ΔT 对参考区/部位/环境的依赖，建议同条件复测与趋势比较。
7. **就医提示**：只用一般性表述列出需要及时就医的表现，不宣称患者已经存在。
8. **表达结构**：中文，先直接回答所问；默认 2–4 句、约 300 字以内，不套用固定四段模板，不复述界面已有信息。
9. **报告边界**：不声称已审核或已出具正式报告。
10. **范围**：只讨论创口温度筛查、随访、报告和本项目证据库。

### 3.1 草稿模式（报告中心打开草稿后自动进入）

- 请求体附带 `draft`（草稿标题、状态、已填详情、补充记录），**测量取草稿内保存的那一份**，不再用界面当前测量；`sanitizeDraftContext()` 只保留这四类字段，不传草稿 id 以外的内部信息。
- 模型在回答末尾输出 `<<<DETAIL>>>{"site":…,"duration":…,"symptoms":…,"treatment":…,"notes":…}<</DETAIL>>>`，表示“从这段对话里提取到的创口详情”。
- 服务端 `splitDetailBlock()` 先剥离该块，再对正文做 `validateAnswer()`；详情交给 `sanitizeDetails()` 过白名单（五个字段、每项 ≤120 字、≤5 条）。
- 界面把 `meta.detail_updates` 渲染为“从刚才的对话提取到补充信息，是否写入草稿？”，**医师点“写入草稿”才调用 `draft.update`**，同时追加一条来源为 chat 的补充记录。模型不能直接改库。
- 已归档草稿只读：不提取详情，只能继续追问解释。
- 模型不可用或余额不足时走规则模板，此时没有 `detail_updates`，详情需在表单里手动填写。

## 4. 数据边界

发送给模型的只有白名单字段（`sanitizeMeasurement()`）：

- `measurement_id`、采集时间、设备型号/模式/标定状态；
- 质量标记（帧数、ROI/参考区有效、量程、警告）；
- 指标（创口均温、参考皮温、ΔT、最高温、面积比、梯度）；
- 阈值版本与阈值数值。

**不会发送**：`patient_ref`、`encounter_id`、姓名/证件号、原始热像、附件路径、数据库路径、密钥。历史消息裁剪为最近 6 轮、每轮 600 字。

## 5. 模型路由与失败回退

- 默认使用 DSH 当前默认模型（`ctx.agentDefaultModel.currentSelection()`），可在插件 `config.assistant` 中覆盖 `provider` / `model` / `maxTokens` / `temperature` / `reasoningEffort` / `timeoutMs`。
- 推理型模型优先选择最低推理档，避免把输出预算耗在思考上（这是实测发现的问题：默认档会因 `max-tokens` 只产出 reasoning）。
- 模型不可用、超时、无输出或被校验拦截时，用本地规则结果生成**按问题路由的短回答**（`fallbackAnswer()`）；复测、证据、就医、报告等问题各有针对性表述，不再统一套四段模板。界面标注“规则模板 · 未使用模型”并写明回退原因。
- 单次请求上限：问题 2000 字、请求体 128 KB、默认 45 秒超时；点击“停止”会中断模型流。

## 6. 只在本机回环地址启用

对话路由 `/wound-clinic/assistant/chat` 只在 Web GUI 绑定回环地址时注册；绑定到局域网地址时不注册并写警告，避免无鉴权的医学对话暴露到网络。路由还校验 `Origin` 与当前 GUI 不一致时返回 403。

## 7. 修改规则

规则、校验正则、快捷提问、等级词表都在 `runtime/physician_rules.json`。文件按 mtime 缓存，保存后下一次提问即生效，无需重启 DSH 或重载插件（修改 `assistant.js` / `index.js` 才需要重载插件）。

## 8. 测试与已知限制

```text
node runtime/test_assistant.mjs       # 脱敏、提示词、校验、兜底、历史裁剪、草稿上下文与 <<<DETAIL>>> 提取
node runtime/test_client_render.cjs   # 客户端渲染冒烟（侧边面板、草稿列表/详情、提取卡片、已归档只读）
python runtime/test_workflow.py       # 保存草稿 → 修改详情 → 归档编号 → 门禁阻断（临时数据库）
```

已在本机用真实 HTTP 请求验证：合规答案放行（含免责声明自动补齐）、确诊/用药/等级篡改/报告越界被拦截、质量门禁阻断时不做风险解释、无测量时只做一般性说明、提示词注入被拒绝、研究人群里的“高风险人群”不会被误判为等级断言。草稿流程的 HTTP 层与真实模型附带 `<<<DETAIL>>>` 块的稳定性尚未在运行中的 DSH 里实测。

已知限制：

- 侧边窗口不能调用工具（写患者档案通过草稿详情页“保存为患者档案”，或在主对话调用工具）；一般对话不进入会话日志，刷新页面后不保留；草稿详情页内的对话随草稿保存。
- 草稿模式下的详情提取依赖模型输出格式，余额不足或超时时不产生提取结果。
- 未接入原始热像；不做实时流。
- 客户端界面需要在页面刷新后加载新 bundle，当前会话未做浏览器截图验收；中文输入法回车、窄窗口布局和暗色主题需要在浏览器中确认。
